# تغییرات — خطای «جدولِ app_releases وجود ندارد» و راهنمای راه‌اندازی

## ۱. خطای `Table 'bookassistant_db.app_releases' doesn't exist`
**علت:** کدِ «نسخه‌های اپ» آمده ولی migrationِ جدولش روی دیتابیسِ شما اجرا نشده است.
باگِ کد نیست.

**راه:**
```bat
php artisan migrate
```
دو جدولِ این هفته را می‌سازد (اگر هنوز ساخته نشده باشند):
- `book_categories` و ستون‌های ترتیب در `books`
- `app_releases`

کتاب‌های موجود دست نمی‌خورند. بدونِ دسته می‌مانند و به ترتیبِ فعلی شماره‌ی ردیف
می‌گیرند.

این دقیقاً روی MySQL با چند کتابِ موجود تست شد.

**برای بعد:** بعد از هر `git pull` این سه دستور را بزنید (در `SETUP-backend.md` هم
آمده):
- `composer install`
- `php artisan migrate`
- `php artisan optimize:clear`

## ۲. باگِ پیداشده: rollbackِ migrationِ دسته‌ها روی MySQL
در تستِ MySQL معلوم شد `down()`ِ migrationِ
`2026_10_12_000001_create_book_categories_and_book_order` روی MySQL خطا می‌داد:
```
1553 Cannot drop index 'books_category_id_sort_order_unique': needed in a foreign key constraint
```
- **علت:** کلیدِ خارجیِ `category_id` از ایندکسِ یکتای `(category_id, sort_order)`
  استفاده می‌کند، ولی ایندکس قبل از کلیدِ خارجی حذف می‌شد.
- **رفع:** حالا اول کلیدِ خارجی و بعد ایندکس حذف می‌شود.
- این فقط در `migrate:rollback` اثر داشت. `migrate`ِ معمولی درست بود و لازم نیست کاری
  بکنید.

## ۳. `.env.example` برای همین پروژه
الگوی قبلی همان پیش‌فرضِ خامِ لاراول بود (SQLite) و کلیدهای این پروژه را نداشت.

**الان:**
- MySQL، دیتابیسِ `bookassistant_db` و کاربرِ root بی‌رمز (مثلِ Laragon).
- `APP_URL=http://127.0.0.1:8000`.
- کلیدهای پروژه با توضیح: `ARCHIVE_UPLOAD_MAX_MB`، `ARCHIVE_UPLOAD_MAX_MINUTES`،
  `PASSWORD_MODE`، `ZARINPAL_MERCHANT_ID`.

`.env`ِ خودِ شما دست نخورده است. این فقط الگوی کامپیوترِ تازه است.

## ۴. `SETUP-backend.md` (تازه)
راهنمای کاملِ راه‌اندازی روی کامپیوترِ تازه، با این بخش‌ها:
1. چه چیزهایی در git نیست و باید پشتیبان گرفت.
2. پیش‌نیازها.
3. php.ini.
4. گرفتنِ کد و `.env`.
5. ساختنِ دیتابیس.
6. جدول‌ها: پروژه‌ی خالی یا انتقال از کامپیوترِ قبلی.
7. ساختنِ ادمین.
8. اجرا برای گوشی.
9. وارسیِ نهایی.

در پایان هم جدولِ خطاهای رایج و راه‌حلشان آمده است. در `ARCHITECTURE-backend.md` به
آن ارجاع داده شده.

## تست
روی یک کامپیوترِ تمیز با MariaDB (هم‌خانواده‌ی MySQL)، طبقِ همین راهنما:
- **راه‌اندازیِ خالی:**
  - همه‌ی migrationها اجرا شدند.
  - ادمین با دستورِ tinker ساخته شد.
  - ورود موفق بود.
  - `/admin`، «کتاب‌ها»، «دسته‌ها»، «نسخه‌های اپ» (فهرست و فرم)، `/app` و
    `/api/app/latest` همه بدونِ خطا باز شدند.
- **ارتقای دیتابیسِ قدیمی:** دیتابیسی در وضعیتِ قبل از دسته‌ها، با سه کتابِ موجود،
  با `php artisan migrate` بی‌خطا ارتقا یافت.
- **تست‌های خودکار:** ۱۸ از ۱۸ پاس.
